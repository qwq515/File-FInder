今天我在调试一个NLP pipeline，主要问题是tokenizer对mixed Chinese-English input处理不稳定。The model itself seems fine, but the preprocessing step sometimes produces unexpected tokens. 比如输入“debug模式已开启”，理想输出应该是["debug", "模式", "已", "开启"]，但实际却得到["de", "bug", "模", "式已", "开启"]。我检查了`config.json`里的`tokenizer_type`，发现默认值是`bert-base-chinese`，但它对英文子词切分不够sensitive。Then I tried switching to a custom regex-based splitter: `re.split(r'([\u4e00-\u9fff]+|[A-Za-z]+|\d+)', text)`. 这个方法在大多数case下works well，but it fails when there are emojis or URLs like `https://example.com/debug?id=42`. 我加了fallback逻辑：如果regex匹配结果包含空字符串，就回退到`jieba.lcut`加英文空格切分。After that, the F1 score on the mixed test set improved from 0.72 to 0.81. 不过还有一个edge case：中文标点“，”和英文逗号“,”混用时，tokenizer会把它们当成不同token，导致downstream model confusion. 我打算明天写个unit test，用`pytest`跑100条mixed samples，并记录`token_count`和`unknown_token_ratio`。Overall, the debugging session was productive, but I still need to check memory usage when batch_size=32. 如果你也遇到类似问题，建议先打印`tokenizer.encode(text)`的原始输出，don’t trust the pretty-printed version. 好了，先写到这里，我要去run `python debug.py --verbose`了。
