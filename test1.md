早上九点，我端着一杯Americano坐到工位，准备fix一个奇怪的bug。The issue is: when I call `fetchData()` with a Chinese query string like `?name=张三`, the backend returns 500 error, but English names work fine. 我先看了Nginx access log，发现request URL被encode成了`%E5%BC%A0%E4%B8%89`，这本身没问题。Then I added `console.log(decodeURIComponent(req.url))` in Node.js, and it printed correctly. 奇怪的是，数据库查询用了`LIKE '%张三%'`，但MySQL的collation是`utf8mb4_general_ci`，理论上应该match。I suspected the connection charset was wrong, so I checked `SHOW VARIABLES LIKE 'character_set_%'`. 结果发现`character_set_client`是`latin1`，而`character_set_connection`是`utf8mb4`。That mismatch caused the Chinese characters to be garbled before reaching the query. 我修改了连接配置：`charset: 'utf8mb4'`，并重启了service。After that, the API returned 200 with correct data. 为了验证，我写了三个test cases：`name=张三`、`name=李四`、`name=John`. 前两个pass，第三个也pass。Now I’m enjoying my second coffee and thinking about adding a middleware to log `req.headers['content-type']` and `req.query` for future debugging. 顺便说一下，mixed-language logging其实很有用：中文描述业务逻辑，English记录error stack，这样team里不同背景的人都能快速理解。比如：`[ERROR] 用户查询失败: invalid token in "debug模式"`。这种格式比纯中文或纯英文都更efficient。好了，bug fixed，我要去review PR了。See you later, and remember: always check your charset!
